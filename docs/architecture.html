Factory Inventory Management System

Architecture overview: system layout, technology stack, and data flow.

System Architecture

A two-tier application. A Vue single-page app talks to a FastAPI service that serves data held in memory.

Tech Stack

There is no database. All data lives in JSON files and is loaded into memory when the server starts.

Frontend

  • Vue 3 (Composition API)
  • Vue Router 4
  • Vite 8 dev server and bundler
  • Axios for HTTP
  • Custom SVG charts, CSS Grid layout
  • English and Japanese locales

Backend

  • Python 3.11+
  • FastAPI with Uvicorn
  • Pydantic 2 models
  • Dependencies managed with uv

Data and tooling

  • JSON files in server/data/
  • generate_data.py builds sample data
  • pytest and FastAPI TestClient
  • scripts/start.sh and stop.sh

Data Flow

How a filter change on the page becomes a refreshed view.

Step detail

  1. Four filters are shared across views: time period, warehouse, category, and order status. State is a module-level singleton in useFilters.js.
  2. The API client drops any filter set to all and sends the rest as query parameters.
  3. Handlers call apply_filters (warehouse, category, status) and filter_by_month (a month such as 2025-01 or a quarter such as Q1-2025).
  4. Pydantic validates the result against a response_model.
  5. Views keep raw responses in refs and derive chart and table data in computed properties.
  6. Inventory has no date field, so it ignores the month filter.

Project Layout

Client

  • client/src/main.js - app bootstrap and routes
  • client/src/api.js - all backend calls
  • client/src/views/ - one page per route
  • client/src/components/ - filter bar, modals, menus
  • client/src/composables/ - filters, auth, i18n state
  • client/src/locales/ - en and ja strings

Server and tests

  • server/main.py - models, filters, routes
  • server/mock_data.py - JSON loader
  • server/data/ - seven JSON datasets
  • tests/backend/ - pytest suites for the API
  • scripts/ - start and stop helpers

Observations

Items found while reading the code that are worth knowing about:
  • api.js calls /api/tasks and /api/purchase-orders, but main.py defines no such routes. Those calls will return 404. Only the request and response models exist.
  • views/Backlog.vue is not imported by the router or any other file, so the backlog page is not reachable by URL.
  • The API base URL is hard-coded to http://localhost:8001 in api.js.
  • Data is loaded once at startup and never written back, so restarting the server resets everything.
